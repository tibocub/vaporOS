# vaporOS on the Waveshare RP2040-Zero

Boots straight into vaporshell on a USB CDC-ACM serial console (`vinit`, no NSH).

## Workflow (from `vaporOS/`)

The board is described by `boards/rp2040-zero/` (see boards/README.md); the
commands are the same as for every other target, with `BOARD=rp2040`:

    make -f dev.mk build BOARD=rp2040   # compile  -> ../nuttx/nuttx.uf2
    make -f dev.mk flash BOARD=rp2040   # `reboot 1` into BOOTSEL, copy the UF2
    make -f dev.mk term  BOARD=rp2040   # vaporshell over USB (picocom; Ctrl-A Ctrl-X quits)
    make -f dev.mk run   BOARD=rp2040   # flash + terminal
    make -f dev.mk show  BOARD=rp2040   # every option of the image and why it is set

(`make -f dev.mk rp2040` builds, flashes and opens the console in one go.)

Press Enter if the prompt doesn't show: `vinit` waits for three Enters
(sent automatically by `term`). The first flash of a fresh board, or one
that is hung, needs BOOT held while plugging in; after that `flash`
needs no button presses. If the board crashes, the watchdog resets it and the
crash record can be read with `xd 2003ff00 96` (see
`patches/nuttx/rp2040-crashdump-waveshare.patch`).

## What is on the board

- `vinit` boots straight into `vaporshell` on the USB console (no NSH); a host
  that disconnects and reconnects gets a fresh shell.
- Tab completion (commands and paths), history, Ctrl-C / Ctrl-D.
- `vi`, `lua` and `vlua` (with a REPL: `vlua`, Ctrl-D to leave), toybox applets.
- NSH-style `free`, `df`, `mount`, `umount`, `ps`, `top`, `uptime`, `dmesg`, `xd`.
- `/flash`: 1 MB LittleFS that survives reflashing (`df` shows the space).
- ~55 KB of the 264 KB RAM used at idle, ~560 KB of the 2 MB flash.

Everything above is the same software as the simulator (`BOARD=sim-nsh`); only the
console, storage and watchdog differ, and those are the `[hardware]` lines of the
board file. Try a change on the simulator first, it needs no hardware.

## One-time host setup

- Toolchain in `~/toolchains`: `arm-gnu/` (Arm GNU 13.x `arm-none-eabi`),
  `picotool/`, `pico-sdk/` (needed for boot2). Override with `ARM_TOOLCHAIN_BIN`,
  `PICOTOOL_DIR`, `PICO_SDK_PATH`.
- Serial permission (the board is `0525:a4a7`):

      echo 'SUBSYSTEM=="tty", ATTRS{idVendor}=="0525", ATTRS{idProduct}=="a4a7", MODE="0666"' \
        | sudo tee /etc/udev/rules.d/99-nuttx-cdc.rules
      sudo udevadm control --reload && sudo udevadm trigger

- `picocom` for the terminal.

## Caveats

- Very fast bulk input is untested since the USB console fixes (it used to wedge it);
  paste in moderate pieces.
- `date` has no RTC to read: the clock starts at 2021-02-09 on every boot until set.
- Needs the patches in `patches/nuttx/` applied to `../nuttx` (`tools/apply-patches.sh`;
  see `patches/UPSTREAM.md` for what each one does and why).
